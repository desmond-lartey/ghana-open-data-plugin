# Describing your data

A good description lets someone else find, trust and reuse your data. These fields matter most.

| Field | Good practice |
|---|---|
| **Title** | What the data is, in a sentence: *Household water sources, Tamale Metropolitan, 2023* |
| **Creators** | Everyone who should be credited, in the order of the publication |
| **Date** | When it was published, not when it was collected |
| **Description** | What was measured, how, where and when; units; known limits |
| **Licence** | CC BY 4.0 is the most common for open data; CC0 waives all rights |
| **Coverage** | National, a region or a district; use the picker |
| **Period** | The years (or dates) the data describes |
| **DOI or link** | The permanent address of the original |

## Formats

Any format is accepted. These are easiest for others to reuse: **CSV** for tables, **GeoPackage** or **GeoJSON** for maps, **GeoTIFF** for rasters. For tables about regions or districts, add the p-code column (for example `GH0701`) if you can.
